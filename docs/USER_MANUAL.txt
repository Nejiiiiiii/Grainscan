## 1. Introduction

### 1.1 What is GrainScan?

GrainScan is an advanced automated rice quality inspection system that uses AI-powered computer vision to analyze rice grain samples. The system provides:
- **Automated Detection**: Uses YOLOv8 instance segmentation to detect and classify individual rice grains
- **Quality Assessment**: Grades rice samples as High, Medium, or Low quality
- **Comprehensive Analytics**: Provides detailed statistics and visualizations
- **Batch Processing**: Analyze multiple images simultaneously
- **Live Camera Support**: Real-time grain capture and analysis
- **Custom Model Training**: Fine-tune models with your own data

### 1.2 Who Should Use This Manual?

This manual is designed for:
- Quality control inspectors
- Rice mill operators
- Agricultural researchers
- Food processing facility managers
- Anyone involved in rice quality assessment

### 1.3 System Requirements

**Minimum Requirements:**
- **Operating System**: Windows 10 or later
- **Python**: Version 3.8 or higher
- **RAM**: 8GB minimum (16GB recommended)
- **Storage**: 2GB free space
- **Camera**: USB webcam (optional, for live capture)
- **GPU**: NVIDIA GPU with CUDA support (Optional for faster processing/slow on CPU)

**Required Python Libraries:**
- ultralytics (YOLOv8)
- opencv-python
- pandas
- matplotlib
- pillow
- openpyxl (for Excel export)

### 2.2 Rice Grain Classification

The system classifies rice grains into **5 categories**:

| Category | Description | Color Code |
|----------|-------------|------------|
| **Long** | Length 6.61-7.50mm, premium quality | 🟢 Green |
| **Medium** | Length 5.51-6.60mm, standard quality | 🟠 Orange |
| **Short** | Length < 5.50mm, sub-standard quality | 🔵 Blue |
| **Broken** | Broken/fragmented grains | 🔴 Red |
| **Discolored** | Discolored/damaged grains | 🟣 Purple |

### 2.3 Quality Grading System

Rice samples are graded using a comprehensive scoring algorithm:

**High Quality:**
- ≥80% dominant grain type (Long, Medium, or Short)
- ≤5% broken grains
- ≤3% discolored grains
- Low defect rate overall

**Medium Quality:**
- ≥60% dominant grain type
- ≤10% broken grains
- ≤8% discolored grains
- Moderate defect rate

**Low Quality:**
- Does not meet Medium quality criteria
- High defect rate
- Poor grain composition

## 4. Main Features

### 4.1 Scan Image (Single)

**Purpose**: Analyze a single rice grain image

**Steps**:
1. Click **"Scan Image"** in the sidebar
2. Click **"Select Image"** button
3. Choose your image file (JPG, PNG, BMP supported)
4. Wait for processing (progress bar appears)
5. View results in the pop-up window

**Result Window Shows**:
- Overall quality grade (High/Medium/Low)
- Quality score (0.000-1.000)
- Grain distribution breakdown
- Annotated image with detected grains
- Detailed statistics

### 4.2 Batch Scanning

**Purpose**: Process multiple images at once

**Two Methods**:

**A. Batch Scan (Files)**
1. Click **"Scan Image"** → **"Batch Scan (Files)"**
2. Select multiple image files (hold Ctrl/Cmd for multiple selection)
3. Wait for batch processing
4. View combined results

**B. Batch Scan (Folder)**
1. Click **"Scan Image"** → **"Batch Scan (Folder)"**
2. Select a folder containing images
3. All supported images will be processed
4. View combined results

**Batch Results Include**:
- Overall batch quality (all images combined)
- Individual image navigation (Previous/Next buttons)
- Combined statistics
- Annotated images for each sample

### 4.3 Live Camera Capture

**Purpose**: Capture and analyze rice grains in real-time

**Steps**:
1. Connect a USB camera
2. Click **"Live Camera"** button
3. Camera feed opens in a new window
4. Position rice grains under camera
5. Press **'C'** to capture
6. Press **'Q'** or **ESC** to quit
7. View analysis results automatically

**Tips for Best Results**:
- Use good lighting (bright, diffused light)
- Place grains on a dark, contrasting background
- Ensure grains are well-separated
- Camera resolution: 1920×1080 or higher recommended

## 6. Quality Assessment System

### 6.1 How Quality Scoring Works

The system uses a **weighted scoring algorithm**:

```
Quality Score = Σ (grain_type_percentage × grain_type_weight)
```

**Grain Type Weights**:
- Long: 1.0 (highest quality)
- Medium: 0.8
- Short: 0.4
- Broken: 0.2
- Discolored: 0.3

**Example Calculation**:
```
Sample: 100 grains
- 60 Long grains   → 60% × 1.0 = 0.600
- 25 Medium grains → 25% × 0.8 = 0.200
- 10 Short grains  → 10% × 0.4 = 0.040
- 3 Broken grains  → 3% × 0.2  = 0.006
- 2 Discolored     → 2% × 0.3  = 0.006
                    ─────────────────
Total Quality Score = 0.852 → HIGH QUALITY
```

### 6.2 Grading Criteria

**Dominant Grain Type Approach**:

The system identifies the dominant grain type (Long, Medium, or Short) and applies specific thresholds:

**If LONG is dominant:**
- **High Quality**: ≥80% Long, ≤15% Medium, ≤5% Short, ≤5% Broken, ≤3% Discolored
- **Medium Quality**: ≥60% Long, ≤30% Medium, ≤10% Short, ≤10% Broken, ≤8% Discolored
- **Low Quality**: Everything else

**If MEDIUM is dominant:**
- **High Quality**: ≥80% Medium, ≤15% Long, ≤5% Short, ≤5% Broken, ≤3% Discolored
- **Medium Quality**: ≥60% Medium, ≤30% Long, ≤10% Short, ≤10% Broken, ≤8% Discolored
- **Low Quality**: Everything else

**If SHORT is dominant:**
- **High Quality**: ≥80% Short, ≤15% Medium, ≤5% Long, ≤5% Broken, ≤3% Discolored
- **Medium Quality**: ≥60% Short, ≤30% Medium, ≤10% Long, ≤10% Broken, ≤8% Discolored
- **Low Quality**: Everything else

### 6.3 Premium Grains

**Premium Grains** = Long + Medium grains

This metric represents the total percentage of high-quality, unbroken grains suitable for premium markets.

**Industry Standards**:
- Premium grade: ≥85% premium grains
- Standard grade: 70-85% premium grains
- Sub-standard: <70% premium grains

### 6.4 Defect Analysis

**Defect Grains** = Broken + Discolored grains

**Target Thresholds**:
- Broken grains: ≤5% (target)
- Discolored grains: ≤3% (target)

**Status Indicators** (in Analytics):
- 🟢 **Good**: Below target thresholds
- 🟡 **Needs Attention**: 1.0-1.5× above targets
- 🔴 **Critical**: >2× above targets

## 7. Model Training & Fine-Tuning

### 7.1 When to Train or Fine-Tune

**Train from Scratch**:
- No existing model available
- Completely new rice varieties
- Different imaging setup

**Fine-Tune Existing Model**:
- Improve detection accuracy
- Add new grain variations
- Adapt to different lighting conditions
- **Recommended**: Start from your best model (e.g., `weightsV6.pt`)

### 7.2 Preparing Your Dataset

**Dataset Structure** (YOLO format):
```
rice_dataset/
├── data.yaml
├── train/
│   ├── images/
│   │   ├── img_001.jpg
│   │   ├── img_002.jpg
│   │   └── ...
│   └── labels/
│       ├── img_001.txt
│       ├── img_002.txt
│       └── ...
└── val/
    ├── images/
    │   └── ...
    └── labels/
        └── ...
```

**data.yaml** template:
```yaml
path: /absolute/path/to/rice_dataset
train: train/images
val: val/images

names:
  0: Long
  1: Medium
  2: Short
  3: Broken
  4: Discolored
```

**Important**:
- Use **instance segmentation annotations** (YOLO segment format)
- Label files contain polygon coordinates, not bounding boxes
- Minimum 100 images per class recommended
- 80/20 train/validation split

### 7.3 Fine-Tuning Step-by-Step

1. **Navigate to Training**:
   - Click **"Train Model"** in sidebar

2. **Configure Dataset**:
   - Click **"Browse Files"** under "Dataset Zip File"
   - Select your prepared dataset (must be .zip)
   - System validates: "✓ Dataset zip selected"

3. **Select Base Model**:
   - **Recommended**: `dataset/weightsV6.pt` (your best model)
   - **Alternative**: `yolov8n-seg.pt` (pretrained segmentation)
   - **Important**: Use `-seg` models for segmentation!
   - Click **"Browse Files"** under "Starting Model Weights"
   - Select model file

4. **Set Training Parameters**:
   
   **For Fine-Tuning** (recommended):
   - Epochs: 5-20 (fewer than training from scratch)
   - Image Size: 640 (standard)
   
   **For Training from Scratch**:
   - Epochs: 50-100
   - Image Size: 640
   
   **GPU Recommendations**:
   - NVIDIA GPU: Keep defaults
   - CPU only: Reduce epochs, expect slower training

5. **Start Training**:
   - Click **"Start Training"**
   - Progress shown in real-time log
   - Training time: 10 minutes - 2 hours depending on:
     - Dataset size
     - Number of epochs
     - GPU availability

6. **Monitor Training**:
   ```
   Training Progress:
   ──────────────────────────────────────
   Unzipping dataset to dataset/training/...
   Found data.yaml at ...
   Normalized data.yaml paths to absolute.
   Loading model weights: weightsV6.pt
   Using dataset: train=...; val=...
   Starting training ... this can take a while.
   
   Epoch 1/10: ████████████░░░░░░░░░░ 60%
   ```

7. **View Results**:
   - Results appear automatically when complete
   - **Metrics Displayed**:
     - mAP50-95: Mean Average Precision (target: >0.7)
     - mAP50: Precision at 50% IoU
     - Precision: Detection accuracy
     - Recall: Detection completeness
   - **Results Graph**: Training curves over epochs
   - **Model Location**: `runs/rice_train_<timestamp>/weights/best.pt`

8. **Use New Model**:
   - Copy `best.pt` to your models folder
   - Navigate to **"Choose Model"**
   - Select the new model
   - Click **"Save Configuration"**

### 7.4 Training Best Practices

**Data Quality**:
- ✅ High-resolution images (1920×1080 or better)
- ✅ Consistent lighting across all images
- ✅ Varied backgrounds to improve generalization
- ✅ Well-separated grains (minimal overlap)
- ❌ Avoid blurry or low-contrast images

**Annotation Quality**:
- Use precise polygon annotations
- Include all visible grains
- Label consistently across images
- Review and correct annotations

**Training Tips**:
- Start with fine-tuning (faster, better results)
- Monitor validation metrics (should improve over epochs)
- If metrics plateau, stop training
- Save checkpoint models every 5-10 epochs

## 9. Troubleshooting

### 9.1 Common Issues

#### Issue: "No rice grains detected"

**Causes**:
- Poor image quality (blurry, low contrast)
- Non-rice objects in image
- Grains too small or too large
- Poor lighting

**Solutions**:
1. **Improve Image Quality**:
   - Use higher resolution camera (≥1920×1080)
   - Ensure sharp focus
   - Use bright, diffused lighting

2. **Optimize Background**:
   - Use dark, contrasting background
   - Remove non-rice objects
   - Ensure clean surface

3. **Adjust Camera**:
   - Position camera closer/farther for appropriate grain size
   - Aim for grains to be 100-300 pixels long in image

4. **Check Model**:
   - Verify correct model is loaded (Choose Model)
   - Ensure model file exists and is valid

#### Issue: "Camera not found" or "Failed to initialize camera"

**Solutions**:
1. **Check Camera Connection**:
   - Verify USB cable is connected
   - Try different USB port
   - Check camera is not in use by another application

2. **Camera Permissions**:
   - Windows: Check camera privacy settings
   - Grant application camera access

3. **Driver Issues**:
   - Update camera drivers
   - Restart computer

4. **Try Different Resolution**:
   - System automatically tries multiple resolutions
   - If all fail, camera may not be compatible

#### Issue: "Model inference failed"

**Solutions**:
1. **Check Model File**:
   - Navigate to **Choose Model**
   - Verify model path is correct
   - Ensure .pt file exists

2. **Model Type**:
   - For segmentation: Use `-seg` models (e.g., `yolov8n-seg.pt`)
   - For detection: Regular models work but less accurate
   - Check model type indicator in Choose Model section

3. **Reinstall Model**:
   - Download fresh model file
   - Reconfigure in settings

#### Issue: "Training failed" or "Dataset paths not found"

**Solutions**:
1. **Check data.yaml**:
   - Ensure paths are correct
   - Use absolute paths (not relative)
   - Example:
     ```yaml
     path: C:/Users/YourName/rice_dataset
     train: train/images
     val: val/images
     ```

2. **Validate Dataset Structure**:
   ```
   ✓ Correct structure:
   dataset/
   ├── data.yaml
   ├── train/images/ (contains .jpg files)
   ├── train/labels/ (contains .txt files)
   ├── val/images/
   └── val/labels/
   
   ✗ Incorrect: Missing folders or files
   ```

3. **Check Annotations**:
   - Label files must match image names
   - Format: YOLO segmentation (normalized polygons)
   - Each line: `class_id x1 y1 x2 y2 x3 y3 ...`

4. **Use Correct Model Type**:
   - For instance segmentation datasets: use `-seg` models
   - Detection models will fail with segmentation data

#### Issue: Poor detection accuracy

**Solutions**:
1. **Image Quality**:
   - Use consistent lighting
   - Ensure high resolution
   - Avoid shadows and glare

2. **Fine-tune Model**:
   - Collect 50-100 images with poor detection
   - Annotate correctly
   - Fine-tune existing model (10-20 epochs)

3. **Adjust Confidence Threshold**:
   - Edit `test_main.py` line 127:
     ```python
     conf_th = 0.4  # Lower = more detections (more false positives)
     ```

### 9.2 Performance Issues

#### Issue: Slow processing

**Solutions**:
1. **Use GPU**:
   - Install CUDA-enabled PyTorch
   - Verify GPU is detected:
     ```python
     import torch
     print(torch.cuda.is_available())  # Should return True
     ```

2. **Reduce Image Size**:
   - System auto-resizes to 1920×1080
   - For faster processing, edit `MAX_WIDTH` and `MAX_HEIGHT` in `test_main.py`

3. **Batch Processing**:
   - Use batch mode for multiple images (more efficient)

#### Issue: High memory usage

**Solutions**:
1. **Close Unused Applications**
2. **Process Smaller Batches**
3. **Use Smaller Model**:
   - `yolov8n-seg.pt` (nano) instead of `yolov8m-seg.pt` (medium)

### 9.3 Export Issues

#### Issue: Excel export fails

**Solution**:
```bash
pip install openpyxl
```

#### Issue: PDF export fails

**Solution**:
```bash
pip install matplotlib openpyxl
```

### 10.4 Model Files

**Supported Models**:
1. **Custom Trained** (recommended):
   - `weightsV6.pt`, `weightsV4.pt`, etc.
   - Trained on rice grain dataset
   - Best accuracy for rice grains

2. **YOLOv8 Segmentation** (pretrained):
   - `yolov8n-seg.pt` (nano - fastest)
   - `yolov8s-seg.pt` (small)
   - `yolov8m-seg.pt` (medium)
   - `yolov8l-seg.pt` (large)
   - `yolov8x-seg.pt` (extra large)

3. **YOLOv8 Detection** (fallback):
   - `yolov8n.pt`, `yolov8s.pt`, etc.
   - Lower accuracy than segmentation

**Model Selection Priority**:
1. Environment variable: `GRAINSCAN_MODEL`
2. config.json: `model_path`
3. Fallback candidates (first existing):
   - `dataset/weightsV6.pt`
   - `dataset/weightsV4.pt`
   - `yolov8n-seg.pt`
   - `yolov8n.pt`

## 11. Best Practices

### 11.1 Image Capture

**Lighting**:
- Use diffused light (softbox or cloudy daylight)
- Avoid direct sunlight (creates harsh shadows)
- Consistent lighting across all samples

**Background**:
- Dark, matte background (black velvet ideal)
- High contrast with white/light rice grains
- Clean, flat surface

**Camera Setup**:
- Mount camera perpendicular to surface
- Fixed distance (consistent scale)
- Focus on center of sampling area

**Sample Preparation**:
- Spread grains in single layer
- Avoid overlapping grains
- Use consistent sample size (50-100 grains)
- Remove foreign objects

### 11.2 Batch Processing

**Organization**:
- Use consistent naming: `sample_001.jpg`, `sample_002.jpg`, etc.
- Group related samples in folders
- Include metadata in filename if needed

**Processing Strategy**:
- Process 10-50 images per batch
- For larger datasets, split into multiple batches
- Regular intervals (e.g., hourly, daily)

**Quality Control**:
- Review batch results for anomalies
- Check individual images if overall quality is unexpected
- Investigate outliers

### 11.3 Model Management

**Version Control**:
- Keep previous model versions
- Naming: `weights_v1.pt`, `weights_v2.pt`, etc.
- Document changes and improvements

**Testing**:
- Test new models on validation set before deployment
- Compare metrics with previous version
- Ensure accuracy improvements

**Backup**:
- Backup trained models regularly
- Store in multiple locations
- Include training configuration

### 11.4 Data Management

**Report Archiving**:
- Monthly: Use "Clear analytics" to archive
- Backup archived data externally
- Keep organized by date/batch

**CSV/Excel Management**:
- Export important results to Excel
- Create summary spreadsheets
- Use pivot tables for analysis

**Long-term Storage**:
- Compress old images and reports
- Cloud backup recommended
- Maintain minimum 1-year retention

## 13. Frequently Asked Questions (FAQ)

### Q1: What image formats are supported?
**A**: JPG, JPEG, PNG, and BMP formats are fully supported.

### Q2: Can I process images from a microscope?
**A**: Yes, but ensure proper scaling. The system works best with whole grain images (not microscopic views of single grains).

### Q3: How accurate is the quality assessment?
**A**: With a well-trained model, accuracy is typically 90-95% compared to human experts. Accuracy depends on:
- Model training quality
- Image quality
- Consistent imaging conditions

### Q4: Can I use this for other grain types (wheat, barley)?
**A**: The system is designed for rice but can be adapted:
- Collect new training dataset for other grains
- Adjust quality criteria in `quality_assessment.py`
- Train new model with appropriate classes

### Q5: How many images should I use for training?
**A**: Recommended:
- Minimum: 100 images per class
- Good: 500+ images per class
- Excellent: 1000+ images per class

### Q6: What's the difference between detection and segmentation models?
**A**:
- **Detection**: Bounding boxes around objects (less precise)
- **Segmentation**: Pixel-level masks (more accurate, recommended)

### Q7: Can I run this without a GPU?
**A**: Yes, but processing will be slower:
- CPU: 5-15 seconds per image
- GPU: 1-3 seconds per image

### Q8: How do I improve detection of small/broken grains?
**A**:
1. Use higher resolution images
2. Fine-tune model with more examples of small grains
3. Adjust confidence threshold (lower = more detections)

### Q9: Can I export data to external systems?
**A**: Yes, CSV export provides raw data for integration with:
- Excel/Google Sheets
- Custom analysis scripts
- Database systems
- ERP/QC software

### Q10: What if my rice variety isn't classified correctly?
**A**: Train a custom model:
1. Collect 100+ images of your variety
2. Annotate with correct labels
3. Fine-tune existing model (10-20 epochs)
4. Deploy new model

## 14. Glossary

**Terms and Definitions**:

- **Annotation**: Labels on training images indicating object locations and classes
- **Batch Processing**: Analyzing multiple images in one operation
- **Bounding Box**: Rectangular box around detected object
- **Confidence**: Model's certainty about a detection (0.0-1.0)
- **Defect Grains**: Broken and discolored grains combined
- **Detection**: Identifying and locating objects in images
- **Dominant Grain**: The most common grain type in a sample
- **Epoch**: One complete pass through the training dataset
- **Fine-Tuning**: Training an existing model with new data
- **GPU**: Graphics Processing Unit (accelerates AI processing)
- **Instance Segmentation**: Detecting and outlining individual objects
- **IoU**: Intersection over Union (overlap measure for detections)
- **KPI**: Key Performance Indicator
- **mAP**: Mean Average Precision (detection accuracy metric)
- **Model**: Trained AI algorithm for detection/classification
- **NMS**: Non-Maximum Suppression (removes duplicate detections)
- **Premium Grains**: Long and Medium grains (high quality)
- **Quality Score**: Weighted score indicating overall rice quality
- **ROI**: Region of Interest (specific area in image)
- **Segmentation**: Pixel-level object detection
- **Training**: Process of teaching AI model from labeled data
- **Validation Set**: Images used to test model during training
- **YOLO**: You Only Look Once (real-time object detection algorithm)
